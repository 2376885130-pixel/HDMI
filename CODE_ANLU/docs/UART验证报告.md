# 星衡双屏系统 UART 三轮修改记录

本副本以用户已上板确认正常的 `D:/FPGA_DUAL_HDMI_AUDIO_SECTOR_FIX_20261019` 为基线。仅新增串口状态事件、六条主题/演示命令及其控制器接入。最终资源、时序与候选文件信息在本报告末尾记录；用户实机验收仍待完成。

## 修改范围

|模块|修改|
|---|---|
|`rtl/subtitle_uart_controller.v`|复用既有 UART 行解析器，加入 T1～T4、M1/M0；输出单拍请求；保留字幕及音频诊断协议。|
|`rtl/subtitle_uart_service.v`|复用原 UART 收发器，加入回复/事件逐行仲裁。锁定发送源直到 LF，避免两种消息字节交错。|
|`rtl/uart_system_events.v`|新增有界事件队列及快照，输出启动、主题、图片呈现及演示状态变化；过载合并并显式报告 OVERFLOW。|
|`rtl/theme_control.v`|在原主题状态所有者中接收 UART 选主题；仅首页有效，取消同时发生的 KEY3 长按进入。|
|`rtl/eval/p_rover_control.v`|在原演示/参数状态所有者中仲裁 UART 请求和实体开关；M0 抑制仍按住的开关组合，保留释放保护。|
|`rtl/tf_image_top.v`|连接原有系统域快照和单拍请求；不增加媒体、视频或存储通路。|

`.al` 新增一个事件模块源文件引用，并将项目路径机械迁移至独立副本；仿真文件列表对应增加该模块。布局种子尝试单独记录，器件、时钟、时序例外、IO 约束及 IP 保持基线设置。

SD/SPI、FAT、BMP/WAV 解码、SDRAM/缓存仲裁、音频末字节修复、主副屏图元、字幕合成及 PCM 波形模块均不修改。E 盘未写入。正式工程及基线保护清单见 `reports/review/protected_before.json`，逐文件核验和 RTL 差异见 `reports/review/uart_audit.json`、`uart_rtl.diff`。

## 三轮完成内容

第一轮增加只读事件，并复用既有物理串口。第二轮增加六条命令，并接入原状态控制器。第三轮检查输入冲突、协议错误、串口并发和原音画功能，完成 TD 综合、物理实现与最终时序门槛后才生成候选 bit。

串口配置：115200、8N1、关闭流控、ASCII 加实际 CRLF；板载 USB-UART 既有 RX F12/TX D12 不变。每条命令必须等待 OK/ERR 后再发下一条。T1～T4 在首页选择主题，仍需长按 KEY3 进入；主题内拒绝 T 命令。M1 在主题内进入演示，M0 退出。没有增加串口加减参数命令。

|情形|优先级与结果|
|---|---|
|系统复位|最高优先级；清空命令、事件及远程演示请求。|
|首页 UART 选主题与 KEY2/KEY3 同时发生|UART 选主题优先，清除 KEY3 计数；不误请求旧主题图片。|
|主题内收到 T1～T4；首页收到 M1|拒绝并回复 ERR CONTEXT，不修改状态。|
|M1 与实体开关|远程演示请求和未抑制的实体组合做逻辑或；远程请求由 M0 清除。|
|SW3/SW4 同时下拨时收到 M0|退出并抑制该组合，直到任一开关拨回，再重新组合进入。|
|进入/退出时按键仍按住|原 guard 等待按键释放，避免操作泄漏给主屏或模型。|
|重复 M1/M0|幂等，不重新初始化模型参数。|
|演示内 KEY4 与加减同时发生|沿用原控制器：KEY4 优先；KEY2 减少、KEY3 增加；同时加减抵消。|

最终紧凑事件结构采用一份正在发送的不可变快照和四类待发状态快照，不对音画施加反压。待发同类状态被更新时合并为最新值并报告 EV OVERFLOW，不保证突发期间每一次状态变化都单独输出。串口发送回复和事件的仲裁单位为完整行。

## 仿真范围与边界

`reports/sim/uart_units.json`：10 项针对性测试。包含真实串行收发、CRLF 单次执行、完整行仲裁、四主题映射、上下文保护、长行/非法字符/超时/帧错误/忙拒绝、旧字幕协议、M0 开关抑制、长按临界点冲突与复位，以及原三秒轮播、模式、音频、波形和 OSD 测试。

`reports/sim/av_uart_final.json` 和 `.log`：项目内真实素材快照的 FAT/文件内容与 RTL 音画并发回归。串口使用实际 50 MHz/434 拍位周期；仅按键、模式等等待定时在仿真中缩短，并核验生成的仿真顶层与原顶层除这些参数外一致。检查解码后的图片逐像素、WAV 精确 PCM、HDMI PCM tap 活动、波形命中、演示期间讲解连续、模式切换、手动换图和长复位重新挂载。

该仿真使用行为级扇区传输和 SDRAM 应用接口模型，不包含 TF 电气信号、真实 SDRAM 芯片时序或 HDMI 接收器。精确像素检查覆盖月球车前两张图；四主题控制映射由控制器测试覆盖，不宣称已仿真全部 32 张素材或替代双屏上板测试。

早期仿真在补充 KEY3 长按临界点修复后主动中止；初次综合也已存档到 `reports/synth_initial`。它们不作为最终 RTL 验收证据。最终测试和构建输入哈希保存在 JSON 中，并在生成候选前逐一复核。

## 时钟、跨域与带宽

串口 RX 沿用原双级同步及采样器；解析、事件监视和主题/演示控制均运行于系统 50 MHz 域。本次新增控制链不新增跨时钟总线。主题/副屏参数仍经原 held/ack 邮箱跨域，在副屏原消隐边界提交。图片事件使用原已同步呈现索引和事务完成状态，不从异步视频信号直接取数。

像素 25 MHz、视频串行化、SD/SDRAM 时钟及所有 PLL 保持原设置。SPI 服务时钟 100 MHz，原初始化分频 248、快速分频 2，对应约 200 kHz 初始化和 12.5 MHz 物理 SCLK；不把服务时钟或系统时钟等同于引脚 SCLK。

UART 事件不读写 TF 或 SDRAM，不增加第二播放器和帧缓存；因此无新增媒体带宽请求。M1/M0 不直接重启主屏讲解。局部事件存储 TD 可映射为分布式逻辑 RAM，不占用 BRAM9K，但仍计入 LUT/物理打包资源。

保留基线已有外部 IO 延迟覆盖不足及 PLL/局部时钟警告，不以删除检查或放宽约束消除。最终报告需列出实际 setup/hold 和检查覆盖；工具通过只说明当前约束覆盖范围内通过。

## 最终执行结果

最终 RTL 的 10 项针对性测试全部通过。真实素材并发仿真完成：四次整帧合计 1,228,800 个像素一致，22,060 个 PCM 样本一致，波形命中 4,487 次，串口事件/回复 16 行；模式/SW1/实体及串口演示/手动切图/长复位全部通过。该回归耗时约 571 秒，日志与输入哈希已保存。

第一版 UART 综合：LUT 17552、FF 11450、BRAM9K 64、BRAM32K 0、DSP 27。基线综合对应 17242、11412、64、0、27；该版增加 310 LUT，没有增加 BRAM 或 DSP。八项事件队列版本已归档至 reports/uart_queue8_revision，不作为当前 RTL 的验证结果。

八项队列版本物理打包尝试 seed8、seed2、seed3、seed4、seed5、seed6 分别需要 4923、4940、4902、4930、4923、4921 个 MSlice，均超过器件 4900 上限。seed1 以 4893 个 MSlice 通过初始打包，但布线冲突持续增长，主动停止并存档至 reports/route_attempts/seed1_interrupted；没有生成 bit。

紧凑事件版本重新完成全部 10 项针对性测试及真实素材并发仿真，像素/PCM/波形计数与前版一致；另补测 31 字节 AUDIO? 诊断回复。本最终回归耗时 586.957 秒。综合结果 LUT 17513、FF 11453、BRAM9K 64、DSP 27。

最终紧凑版在 seed12 完成完整布局布线、hold 优化和 final STA：LUT 18077/19600、FF 11368/19600、BRAM9K 64/64、BRAM32K 0/16、DSP 27/29。全设计 SWNS +0.220 ns、HWNS +0.030 ns、STNS/HTNS 均为 0，DRC 无多驱动和异常时序路径。布局后 LUT 相对本次同环境基线增加 249，未增加 BRAM 或 DSP。较早紧凑版 seed2/7/10/11 打包失败保留于 reports/route_attempts；seed12 是最终采用结果。

串口新增命令、演示控制及事件有效信号通过明确网名解析后，抽查各 16 条 setup/hold 路径，全部非负；详细最小裕量见 reports/review/uart_timing.json。初次复核脚本使用多个通配符组合，未正确限定路径，且把 removal 误当作 hold 检查；已修正为逐个解析控制网名并严格检查报告类型，重新通过复核。此问题只影响复核脚本，未修改最终 RTL 或约束。

check_timing 检查项计数与基线一致：no clock、无效约束、组合环、被遮蔽/忽略例外均为 0。仍有原有 10 个未设置输入延迟端口、29 个未设置输出延迟端口、4 类 dummy node 与 2 项 PLL 反馈网络警告，不能据此宣称板级所有外部接口时序已被覆盖。

独立面积试验副本的回复重编码及移位输出均未纳入本次候选；最终 RTL 为完成上述仿真并通过 seed12 布线的紧凑事件版本。保护清单 385 文件核验通过，正式工程、稳定版、读卡/SDRAM/BMP/WAV/时钟/IP/素材不变。候选 bit 的最终哈希、资源、时序及待上板状态由 reports/candidate/release.json 记录。
